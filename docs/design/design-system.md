# 设计系统:tokens 语义与配色规则

> 返回 [文档索引](../README.md)
>
> **改配色前先读这一篇。** 具体取值读 `src/renderer/theme/tokens.css`(唯一来源),这里只写每个 token 归谁用、底线在哪、以及会复发的坑。

## 两个正交轴

- `data-mode` = `light | dark` —— 明暗**品牌外壳**(chrome:bg / surface / border / text / brand / 阴影 / 辉光)的**默认档**。用户偏好里还有「跟随系统」一档,由 `SettingsProvider` 解析后才落到属性上,**属性本身永远是这两值之一**,tokens 不必也不该写 `prefers-color-scheme`。
- `data-theme` —— **配色主题**,成套打包所有该随主题走的部件:语法 token + 代码正文色、diff 增删的前景 / 背景 / gutter、severity 徽标色、代码内引用与搜索高亮。主题跟随 `data-mode` 自动切子模式。有哪几套、各自取什么值,读 `tokens.css`。

**主题默认只管代码那一半,chrome 由 `data-mode` 给;但主题可以整套覆写 chrome** —— 纸的色温本身就是羊皮纸这套主题要传达的东西,只换语法色留一块冷灰画布等于没做。覆写档的选择器带两个属性(`[data-mode][data-theme]`),特异性高于 `data-mode` 那档,与书写顺序无关。**duet 双声道 accent(agent 天蓝 / human 琥珀)由 chrome 给出默认值,主题可按自己的画布覆写** —— 要守住的是**两条声道的语义角色与彼此、与 severity / diff 的可辨识度**,不是某个固定色值;把色值锁死等于规定了以后所有配色方案的画布色温。羊皮纸这一版就是照此各选各的:agent 天蓝原样(冷 accent 压在暖纸上最跳,信息层级一点不用重排),human 琥珀微调一档补偿暖纸吃掉的暖意。GitHub 这一版走到了另一头:agent 改用 Primer 的 done 紫,因为**蓝在 GitHub 的语言里属于链接与导航** —— agent 继续占蓝就会与满屏链接、与主 accent 撞,而紫恰是 GitHub 给「机器人 / 已合并」的那一档;让出蓝之后 severity 的 low 才能安心用蓝。屏幕特有的布局变量(如栏宽)留在各屏自己的 CSS。

**主题换的不只是色值,还有文法口味。** 语法槽分主槽(`--k/--fn/--s/--n/--c/--ty/--mac`)与跟随槽(`--lit` 字面量 / `--tag` 标签 / `--prop` 属性 / `--re` 正则 / `--c-style` 注释字形),跟随槽默认并回主槽,只有归类与 duetlens 不同的主题才把它们拆开 —— GitHub 把字面量算常量、标签独占一档、属性不与类型同色、`this` 与预处理算关键字、注释从不斜体,橙色只留给类型 / 类名。**只对齐色值不对齐归类,逐 token 仍然对不上**,而这正是「看着像 GitHub 但就是不对」的来源。取值一律照 Primer 现行档抄(退役值如注释 `#8b949e`、浅色 entity `#8250df` 会一直骗人),差异明显的几处直接对着真实 GitHub 页面核。

> 覆写 chrome 的主题**必须把 THEME 变量给全**:`data-theme` 不是 `duetlens` 时,`duetlens · light` 那组不匹配,缺哪个变量就掉回 `:root` 的**深色**值(不是浅色),漏一个就是一处白底浅字。

**浅色档不是把深色调亮,是换一种成像方式。** 赛博朋克这一版的教训:第一稿只把夜色的色相搬到近白画布上,结果与「紫调的 duetlens 浅色」没有区别 —— 霓虹在白天不发光,能留下的只有**色相与色块**。三件事得一起做才立得住:画布真的带色温(不是近白灰,白卡片才有得浮);**前景与底色分开取色**(文字要深才能读、色块要亮才是霓虹,`-soft` / diff 底 / 命中底一律从各自的**亮档**现推,从深前景 `color-mix` 只会得到脏灰蓝);色块面积整体放大一档。放大之后记得回头验一遍落在这些底上的字 —— 底越浓,压在上面的注释掉得越快。

**实心 CTA 的明度有上下两条闸,方向取决于字是深是浅。** 白字那条已经写在上面(hover 压深只会让对比更好)。反过来,**亮底 + 近黑字**(终端的反显光标那种)在这两头都会翻面:hover 压深会**降低**对比,底太亮又会让 `disabled` 的 `opacity` 压不住 —— 按钮明明点不动却仍在发光。定标时拿「实心块对卡片的抬起量」去对齐现有主题(约 3.7:1),别只看字对底。

**主题可以自认「发光」,但光要从一个 token 出。** `--glow-accent` 是实心主按钮往外溢的那圈光,默认值是**一条不可见的阴影**(`0 0 0 0 transparent`)而不是 `none` —— 组件里因此可以无条件写 `box-shadow: var(--glow-accent)`,不必按主题分支,新加的实心按钮跟着抄这一行即可。点亮它的主题注意两点:光要取比按钮本体**更亮**的一档(拿 `--accent-solid` 自己去发光,在夜色里几乎看不出来),浅色档则只留一圈近处的溢色(浅底上大半径光晕会糊成一团脏色)。

新增主题后按两条口径验:**逐屏跑对比度、并与现有主题逐条比差集** —— 只看绝对不达标数会被一批「本来就这样」的装饰性字形(diff gutter 的 ＋ ／ −、off-diff 的 ◇)淹掉,真正要拦的是**只有新主题才有的那几条**。羊皮纸这轮就是这样揪出两处:注释色整行落在 add/del 行底色上(只按画布验合格、压到 del 行不合格),以及 `--text-faint` 落在 `--surface-3` 的 chip 上 —— **两档的下限都由最亮的那层底定,不是由画布定**。

> 检索命中色**独占靛紫色相**,不借用 agent 蓝 / human 琥珀 / diff 绿红任何一档语义。

## 表面阶梯:`--bg` → `--surface` → `--card`

`--bg` 是最「远」的画布(外壳缝隙、中栏代码井),`--surface` 抬起成面板(三栏、rail、顶栏),`--card` 是卡片与列表行 —— **`--card` 永远是三者里更亮的那个**。浅色曾把这条阶梯写反,卡片于是陷进面板里,三栏糊成一片。

**深色下 `--card` 与 `--surface` 同值是有意的**,不是漏改:深底上一根边线就够读出抬起 —— 但边线得真的看得见(曾只有 1.24:1,抬起这件事其实没被传达)。浅色近白面上边线会糊,只能靠填充差,`--card` 才拉到纯白。组件因此一律写 `--card`,不必分模式判断。`--surface-2/-3` 表示卡片**内部**的凹陷(引用块 / 输入框 / chip),两个模式都朝远离 `--card` 的方向走。

> 只改 tokens 取值治不好「区分度差」—— 若卡片与它所在面板本来就同色,那是 CSS 层的问题,得先拆出一个 `--card` 才有得可调。

## 文字阶梯:最低的一档**文字**仍必须能读

| token | 归它的表达 | 底线 |
| --- | --- | --- |
| `--text` | 标题、正文主体 | —— |
| `--text-dim` | 次要内容、元信息、**未选中但可点的分段项** | —— |
| `--text-faint` | 提示、说明、剔除理由、小标签、状态栏 | **≥ 4.5:1** |
| `--text-deco` | 只给非文字与明确失效态:分隔点、spinner 轨道、行号、已剔除项的删除线标题 | 低于 4.5 是有意的 |

判断「是不是失效态」看**它还能不能点**:已剔除的 finding 不再进 review 产物,归 `--text-deco`;而**已看的文件行仍可点、仍要按文件名认出来再打开**,文件名必须留在 `--text-faint`,已看只由删除线 + 绿勾表达。

`--text-faint` 与 `--text-deco` 曾是同一个值 —— 一个 token 干两份工,于是**所有提示文案被装饰的亮度按住**(review 屏一屏 96 处文字不达标)。**改文案颜色前先分清这处是「要读的」还是「装饰」,别把两档重新合上。**

两条容易复发的推论:

- **未选中 ≠ 失效。** 分段选择器的未选中项走 `--text-dim`;用 `--text-faint` 会让二选一长得像单个按钮。真正 disabled 才配 `--text-deco` + `opacity`。这类控件散落在各屏且命名不统一,**改口径时按「有选中态的按钮组」这个性质去找,别按 class 名清单找** —— 名字清单会随重命名变成假的,必漏。
- **阻断性提示不是脚注。** 解释主 CTA 为什么点不动、或「整份会被 422 拒」这类前置条件,至少 `--text-dim` + 警示标记。

## 语义色当填充时前景要跟着翻

`--sev-high/-med/-low` 是**给文字调的**:深色下是浅色调,浅色下才是深色调。所以拿它们做实心填充时,前景必须用随模式翻转的 `--on-accent`,不能用只配 `--accent-solid` 那种两模式都深的底的白字 —— 白字压浅红只有 2.66:1。

反过来,实心按钮**内部**的小垫子(计数徽章、⌘ 提示)要往**深**走(`rgba(0,0,0,.22)`),不能用半透明白:白垫会把底色冲淡成更亮的蓝,压在上面的白字于是比按钮标签本身还难读。深垫同时对上了 `--surface-2/-3` 那套「内部凹陷」的语义。

推论:

- **给主按钮定底色要留余量**,不能刚好卡在 4.5 —— 按钮上任何半透明层都会把实际对比度再拉下去。
- **实心按钮的 hover 不能用 `filter: brightness()` 提亮**:filter 作用于整个元素,白字已经到顶只有底会变亮,对比度必然下降(hover 时重新不达标)。统一走压深的 hover 变量,压深只会让对比度更好。换掉 filter 时注意:`filter` 与 `background` 不冲突,所以原来一条 hover 能盖住所有变体;改成 `background` 后,**同权重但更靠后**的变体规则会把它压掉,必须各补一条,否则那些变体会静默失去反馈。
- **选中态的浅色底会吃掉一档对比度**:`-soft` 底把选中项抬亮后 `--text-faint` 会掉到 4.2–4.3。凡是「选中项里还有一行说明文字」的地方,给选中态单独提到 `--text-dim`。

## 四条语义轴不共用色相

界面上同时有四套含义在用颜色,必须各自独占,否则一个颜色有多个意思:

| 轴 | 归它的表达 |
| --- | --- |
| Severity | `--sev-high/-med/-low` 三个色相;chip 的底与边线由本档现推 |
| 双声道 | agent / human 各占一个色相区(默认天蓝 / 琥珀,主题可换,见上),只落在卡片左脊与署名 |
| 轮次状态 | 全中性,靠字重排序;只有「已修复」用绿。判据是**标签文字本身已说清状态,颜色是冗余且冲突的第二通道** |
| Diff | `--add` / `--del`,只做行底色与 gutter,不做 chip 填充 |

曾经的耦合:severity 三档分别借 diff 红 / human 琥珀 / agent 蓝,轮次的「仍存在」又是红、「新增」与「作者已回应」又都是蓝 —— 没有一个颜色只有一个意思。加 severity 档位或轮次状态时,先确认新值不落进别的轴。

## 品牌标记

含义是**镜片压在一页代码上**:镜外密排细行是上下文,镜内被放大的三行分别是灰(上下文)、天蓝(agent)、琥珀(human)。

手写 SVG 是单一来源,按渲染尺寸分三档美术(`build/logo/`):完整档(≥128px)→ 去掉镜外细行(32–64px,那些 3.4pt 的行到这个尺寸会糊成噪点)→ 再去掉内圈与灰行,只留镜圈 + 两行(16px)。`icon.icns` / `icon.png` 是产物,由脚本从这三个 SVG 生成并已提交进仓库(打包机因此不需要 `rsvg-convert`)。改完 SVG 记得重跑生成命令;打包配置显式指向 `.icns`,不让 electron-builder 从单张 png 自动缩 —— 那样会丢掉分档美术。

界面里不另画一份几何,`LogoMark` 直接读同三个 SVG,只做两件事:把固定色板换成随明暗 / 配色的变量,把 `defs` 的 id 按实例改写(多处同时挂载时 clip 不串)。分档阈值按 CSS px 折半(屏上是 2x 矢量渲染)。

**评审图标的规矩**(踩过):

- **先锁概念再调参数** —— 换概念要先问。
- **主图与小尺寸变体必须共享轮廓**,退化只能「减层」不能换骨架。
- 一定要**同时给 32px / 18px 的小尺寸压力测试**,低对比的细节在大图上看着没事,缩了就没。
- **已否决勿再提**:双环 Venn / 光圈 / 双色放大镜 / 对话双泡 / vesica 镜眼 / 问号融合(五种画法都试过,「看了下都不行」)/ 透镜剖面聚焦。
