01 — 机审边扫边落
01 · 机审

Findings 不是终点，
是对话的锚点

Reviewer 和 agent 同步进行审查，agent 扫出的 finding 会逐步落到 diff 上。

  • 三种来源: GitHub PR · 本地 git 分支 · GitButler 虚拟分支
  • 两档强度: 标准档单轮直接上报，对抗档追加一轮自检
  • 专注审查: agent 跑在 read-only sandbox 里，不做改动。
02 · 讨论

是误报，
还是真漏洞？

每条 finding 都可以被继续讨论；行内 ✎ 或框选一段代码也可新开讨论。彻底搞懂实现细节。

  • 追问: 质疑 agent 的结论或者补齐 agent 不知道的上下文
  • 发现: 主动提出代码改进建议，并让 agent 自动补齐意见
  • 修订: 根据讨论结果，agent 会更新自己的建议
03 · 复核

重跑一轮,
同时采纳多方意见

每轮换一个新会话全量重扫，复核之前发现的问题，同时对于 Reviewer 或者作者明确表态的意见处置会被保留。

  • 复核: 人工主动的处置会得以保留
  • 追溯: 历史讨论和轮次信息得以保留
04 · 收口

提交成 PR review,
或导出 Markdown

人工筛一遍真正要提交的内容，提交成 GitHub PR review。本地分支就导出成一份 Markdown 报告。
